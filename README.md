# Футбол МГУ

Сайт студенческих футбольных турниров МГУ: расписание и результаты матчей,
турнирные таблицы, статистика команд и игроков. Судьи ведут протокол матча
прямо с телефона — события появляются на сайте по ходу игры.

Замена для footballmsu.ru, по устройству ближе к sofascore.com.

---

## Быстрый старт

Нужны **Node.js 20+** и **PostgreSQL 14+**.

```bash
npm install                 # поставить зависимости
cp .env.example .env        # создать файл с настройками и заполнить его
npx prisma migrate deploy   # создать таблицы в базе
npm run db:seed             # заполнить базу демонстрационными данными
npm run dev                 # запустить сайт
```

Сайт откроется на http://localhost:3000

В `.env` нужно заполнить две строки:

```
DATABASE_URL="postgresql://пользователь:пароль@localhost:5432/имя_базы?schema=public"
AUTH_SECRET="любая длинная случайная строка"
```

Секрет можно сгенерировать командой:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

### Тестовые аккаунты

После `npm run db:seed` в базе появятся аккаунты с паролем `football2025`:

| Кто | Email | Что может |
| --- | --- | --- |
| Организатор | `admin@msu.football` | всё |
| Судья | `referee1@msu.football` … `referee4@` | вести протокол любого матча |
| Капитан | `captain.mehmat@msu.football` и другие `captain.<команда>@` | заявку своей команды |
| Зритель | `viewer@msu.football` | только смотреть |

Демо-данные строятся относительно текущей даты: 4 тура уже сыграны, один матч
идёт прямо сейчас, остальные впереди. В обоих турнирах заранее собрана сетка
плей-офф — можно посмотреть, как выглядят незаполненные слоты. Пароль задаётся
переменной `SEED_PASSWORD` в `.env`.

## Как это работает

### Роли

* **Организатор** — создаёт турниры, дивизионы, команды, игроков и расписание,
  назначает судей, заводит аккаунты. Может вести протокол любого матча.
* **Судья** — ведёт протокол любого матча. Назначения показываются отдельной
  вкладкой «Мои», но взять чужой или ничей матч можно одной кнопкой: в лиге
  судью меняют и за пять минут до игры. Кто что внёс, видно в журнале.
* **Капитан** — редактирует заявку состава своей команды.
* **Зритель** — вход не нужен, весь публичный сайт открыт всем.

### Ведение матча судьёй

Раздел «Матчи» → нужный матч (вкладки «Мои», «Сегодня», «Все ближайшие»).
Интерфейс рассчитан на телефон:
крупные кнопки, всё событие вводится в два-три касания.

1. **Составы** (необязательно) — отметить, кто в старте, кто в запасе.
   Если состав не заполнен, выбирать можно любого игрока из заявки.
   Игровые номера тоже необязательны — у части команд их просто нет.
2. **Начать матч** — запускаются игровые часы. Дальше кнопки ведут по
   ходу игры: перерыв → второй тайм → завершить. Есть доп. время
   и серия пенальти для кубка.
3. **Событие** — кнопка «Гол» под нужной командой открывает окно, где уже
   подставлена текущая минута: выбрать автора, при желании ассистента,
   записать. Так же вводятся карточки, замены, автоголы и пенальти.
4. **Правка** — любое событие в протоколе открывается касанием: можно
   изменить минуту, игрока, тип или удалить. Счёт пересчитывается сам.

Матч можно править и после финального свистка — например, дозаполнить
протокол вечером. Все изменения попадают в журнал: видно, кто и когда правил.

Пока матч идёт, страница матча у зрителей обновляется сама каждые 20 секунд,
а минута на табло тикает в реальном времени.

### Дивизионы и плей-офф

Турнир может состоять из нескольких дивизионов, которые играют изолированно —
у каждого своё расписание и своя таблица. Поверх них можно построить **общий
плей-офф по любым правилам**.

Матч плей-офф создаётся заранее — с датой, полем и судьёй, — а вместо команды
указывается, **откуда она возьмётся**:

* «1-е место дивизиона А» — подставится, когда дивизион доиграет регулярный этап;
* «победитель матча №12» или «проигравший матча №12» — подставится сразу после
  того, как тот матч завершится.

Так сетка публикуется до старта плей-офф: болельщики видят «Победитель 1/4 №2»
на своём месте, а команда появляется автоматически. Каскад работает вглубь:
доиграли полуфиналы — финал и матч за 3-е место заполнились сами.

Собирается сетка в разделе **Управление → турнир → Сетка плей-офф**. Кнопка
«Обновить участников» показывает отчёт: почему слот пуст («дивизион ещё не
доигран», «матч завершился вничью — внесите серию пенальти»).

Важные детали:

* если результат матча откатили или исправили, зависимый слот **очищается сам** —
  в финале не может повиснуть команда, которая туда не проходила;
* матч, который уже начался, никогда не подменяется — об этом будет строка в отчёте;
* матчи плей-офф **не идут в круговую таблицу**, но их голы **учитываются**
  в списке бомбардиров.

### Что считается автоматически

Ничего не хранится «предпосчитанным» — всё выводится из событий матча:

* счёт (автоголы засчитываются сопернику);
* турнирная таблица: очки, разница мячей, форма последних матчей;
* бомбардиры, ассистенты, карточки, сыгранные матчи;
* статистика команды и карточка игрока.

Поэтому исправление протокола сразу и правильно меняет всё остальное —
таблица и статистика не могут разойтись с фактами.

## Устройство проекта

```
prisma/
  schema.prisma       описание базы данных
  migrations/         история изменений схемы
  seed.ts             демонстрационные данные
src/
  app/                страницы сайта (маршрут = папка)
    page.tsx            главная: матчи по дням
    tournaments/        турниры, таблицы, расписание, бомбардиры
    matches/[id]/       страница матча с хроникой и составами
    teams/, players/    команды и игроки
    stats/              общая статистика
    referee/            консоль судьи
    captain/            кабинет капитана
    admin/              управление
  components/         переиспользуемые куски интерфейса
  lib/
    football.ts         футбольная логика: счёт, таблица, часы, словари
    stats.ts            расчёт статистики
    auth.ts, session.ts вход и роли
    format.ts           даты и время (везде московское)
    prisma.ts           подключение к базе
  server/             серверные действия (запись в базу)
  middleware.ts       не пускает посторонних в закрытые разделы
```

### Основные таблицы

| Таблица | Смысл |
| --- | --- |
| `Tournament`, `Division` | турнир и его дивизионы/группы |
| `Team`, `Player`, `Faculty` | справочники команд и игроков |
| `TournamentTeam` | заявка команды в конкретный турнир |
| `RosterEntry` | заявка игрока за команду в этом турнире (номер, позиция) |
| `Match` | матч: статус, время, судья, счёт, игровые часы, источник участника для плей-офф |
| `MatchLineup` | состав на конкретный матч |
| `MatchEvent` | голы, карточки, замены — единственный источник правды |
| `User` | аккаунты с ролями |
| `AuditLog` | кто что менял |

Заявка привязана к паре «команда + турнир», а не к команде вообще: игрок
может за сезон сменить команду, и статистика прошлых турниров при этом
не переписывается.

## Полезные команды

```bash
npm run dev        # разработка (сайт на localhost:3000)
npm run build      # сборка для продакшена
npm start          # запуск собранной версии
npm run db:seed    # перезаполнить базу демо-данными (удаляет всё!)
npm run db:studio  # визуальный просмотр базы в браузере
npm run db:migrate # создать новую миграцию после правки schema.prisma
```

### Если Prisma ругается на теневую базу

`npm run db:migrate` требует прав на создание баз. Выдайте их пользователю
базы (от имени суперпользователя PostgreSQL):

```sql
ALTER ROLE имя_пользователя CREATEDB;
```

Без этих прав применять уже готовые миграции всё равно можно:
`npx prisma migrate deploy`.

## Что стоит сделать дальше

Осознанно не вошло в текущую версию:

* загрузка файлов — логотипы команд и фото игроков сейчас задаются ссылкой;
* автоматическая жеребьёвка и готовые шаблоны сеток — сетка собирается вручную,
  зато под любые правила;

* дисквалификации: подсчёт карточек есть, автоматический пропуск матча — нет;
* публичная страница «Судьи» и статистика по судейству;
* уведомления о начале матча.
